# Windows 服务端与个人端

用户安装与登录步骤见 [Windows 双端快速入门](windows-two-role-quickstart.md)。本文保留技术边界和本轮验证范围；候选资产仍待打包与完整工作台启动验收。

服务端运行独立 Django 台账服务和 PostgreSQL。个人端先打开服务器连接窗口，由用户填写地址，再使用服务端创建的账号登录。程序包不附带账号、密码、连接地址或用户设置。

首次双击服务端入口时，`Start-Server.ps1` 调用原安装器；用户自行填写首个管理员用户名和密码。后续启动复用安装与数据。首次安装中断且尚无有效管理员时，同一入口继续账号创建。默认数据在 `%LOCALAPPDATA%\TradeLoomEnterpriseServer`，HTTP 为本机 27417，数据库为本机 56427。关闭启动终端不会停止后台服务；停止请运行 `Stop-EnterpriseServer.ps1`，随后仍可用同一个启动入口重新启动。

管理员从服务器 `/admin/` 创建日常用户并分组：负责人分配“企业老板”；登记员分配“工厂登记员”，另加入以“工厂:”开头的工厂组。普通业务用户不勾选职员或超级管理员。首次管理账号只用于账号管理。

个人端菜单“个人端 → 打开完整工作台”打开个人端程序旁 `Workbench/启动工作台.exe`。这个固定路径只由 Electron 主进程使用，远端网页不能指定程序或路径。没有附带 Workbench 的独立台账客户端仍可正常连接，工作台菜单显示禁用。

企业台账数据与权限由服务端数据库管理；个人端不运行台账数据库。随附的完整 r15 工作台保留原有主题、助手和本地业务功能，仍使用自己的工作台数据目录。两套数据不自动共享；DSH 模型账号与 Django 企业账号也不共用。此交付不将完整工作台的本地业务或 AI 主机改造成远端多用户服务。

## 本次实际验证

基线 `d625cfd`；使用 r15 自带 Python 3.12 和 PostgreSQL 17，以及独立客户端固定 Electron 45.4.1，在项目外隔离目录运行。未修改现有 3088、3090、55432 服务、代理或防火墙。

- `C:/tl618-next/server-personal-qa2`：真实 PostgreSQL 56429、HTTP 27419。正常登录与 CSRF；未登录重定向；登记员登记及私有记录读取、不同登记员隔离；老板读取合成批次、产品及全部登记并写入；管理员用户与用户组页面；POST 退出使 session 失效。`status.json`、`django.log`、`factory-http.json` 留存实际结果。同工厂成员可读共享记录，外部登记员不可读，老板可读，普通登记员不能进入账号管理。
- `electron-owner.json`、`electron-registrar.json`：真实 Electron 生产 main 连接上述服务并用两种合成角色登录成功，远程页面无 preload 与 Node。`electron-menu.json` 另外确认全新配置地址为空、存在工作台菜单；未附工作台的独立客户端菜单禁用且登录正常。
- `C:/tl618-next/server-personal-install-qa`：真实安装独立运行时、数据库与迁移；交互终端自行输入合成管理员，创建成功。修复 Windows PowerShell 5.1 未加载 `System.Net.Http` 导致健康检查误报；实测同一入口重复启动复用服务、停止、再次启动及停止。健康检查仅直连固定 loopback，不更改代理配置。
