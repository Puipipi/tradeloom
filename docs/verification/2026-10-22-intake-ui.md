# 资料整理与生产需求草稿验证

本次复用现有资料整理页，不增加场景或侧栏入口。来源、文字说明、字段映射、待确认候选与生产需求草稿在同一页呈现。样式使用既有日夜主题、字体、边距和焦点样式。

## 本次行为

- 创建草稿前必须明确选择“历史参考”或“新需求”；刷新后可以查询并打开已有草稿。
- 字段按基本信息、数量与包装、交付要求分组。修改依据按需展开；单元格出处可就地查看，文字出处可按行翻页。
- 修改只追加版本。历史版本只读，数量核算使用该历史版本的值。未保存的修改不能确认；版本冲突保留输入，提供明确的重新读取操作。
- 人工改值不自动继承原单元格来源。可以保留待确认，或显式关联未核实的说明摘录及行范围。说明摘录不代表完整录音或已核听原音。
- 需求确认与包装核对分别表示。单位关系须人工明确确认；需求确认不代表可以生产、已排产或已提交 ERP。
- 文本上传与读取保持私有存储；代理只为两条明确的上传路径补齐缺失的长度，不改变其他路由。

## 可复现检查

后端测试使用项目外的受管 PostgreSQL 测试运行器，固定端口 55435，并为每轮建立唯一测试库。禁止将测试目标切到业务主库。

```powershell
node <测试运行器>/run-django-tests.mjs test --test-db <全新唯一测试库> workbench.tests.test_intake_evidence workbench.tests.test_production_requirement workbench.tests.test_pages
```

页面交互测试使用 [jsdom](https://github.com/jsdom/jsdom)，固定版本写在 shell 包的开发依赖及锁文件中。它执行实际页面脚本，网络响应使用合成数据；不会打开或控制桌面软件。Node.js 24.16.0 已用于本次验证。

依赖可安装在项目外。将 `TRADELOOM_DOM_MODULE` 设置为该安装位置的 `jsdom/lib/api.js`；常规开发或 CI 安装 shell 开发依赖后可省略该变量。

```powershell
node --test packages/tradeloom-shell/tests/intake-ui.test.js packages/tradeloom-shell/tests/business-proxy.test.js
```

DOM 检查覆盖用途选择、确认、未保存状态、旧版只读与核算、修改依据、零值、文字原样保留、迟到响应、冲突、文本重试和出处查看。代理检查覆盖两类 multipart 的长度、大小、中断、原始字节，以及既有 JSON 和路由行为。官方 WebServer 前缀契约测试还需要设置 `TRADELOOM_DSH_WEBSERVER_LIBRARY`，缺少时会明确跳过。
