## 三、为什么不是「一个库搞定」

三条路都试过，结论是这样：

| 路线 | 排版能力 | 中文 | CMYK/PDF-X | 结论 |
|---|---|---|---|---|
| ReportLab 直接画 | 精确，但版式要手写坐标 | ✅ 注册 TTF 即可 | 靠 Ghostscript 后处理 | **首选**（确定性强，可程序控制） |
| HTML/CSS → Chromium 打印 | 最强，改版式最快 | ✅ 浏览器自动嵌入 | 靠 Ghostscript 后处理 | 备选（版式复杂时切换） |
| Word/PPT 模板替换 | 弱 | ✅ | ❌ 很难控 | 不做 |

**关键认知**：无论走哪条，最后一步永远是 **Ghostscript 转 CMYK + PDF/X**。所以先把它焊死，排版方式随时可换。

## 四、踩过的坑（省得再踩）

1. `winget install ArtifexSoftware.GhostScript` 在这台机器上**找不到包**（winget 源不全）。直接从 GitHub 下 exe 更可靠。
2. Ghostscript 安装包支持静默安装：`gs10080w64.exe /S /D=<目录>`，装到用户可写目录**不需要管理员权限**。
3. ReportLab **不支持 OTF/CFF 字体**，只吃 TTF。思源黑体官方发的是 OTF，所以这里用 Noto SC 的 TTF 版本。
4. 验证 CMYK 不能只看文件大小或截图。要看内容流算子：转换前是 `rg`（RGB），转换后必须是 `k`（CMYK）。**黑色文字转成灰阶 `g` 是正常的**，别把它当失败。
5. 内容流默认是压缩的，直接当字符串搜 `"k"` 永远搜不到——必须解压后再解析（`pikepdf.parse_content_stream`）。

## 五、本机 Django/PostgreSQL 工作台的启动与迁移

下面步骤适用于本机 PostgreSQL 工作台。每次在同一个 PowerShell shell 中先显式设置数据库、测试数据库和媒体路径，再运行身份 guard、备份、migration plan、迁移和服务启动；不要依赖隐式默认值。密码只从本机密码文件读取到当前进程环境，不回显、不写入项目；`TRADELOOM_SECRET_KEY` 沿用当前本地配置或现有启动脚本的 fallback，不打印或轮换。

```powershell
$projectRoot = (Resolve-Path .).Path
$python = Join-Path $env:LOCALAPPDATA 'TradeLoom\python-env\Scripts\python.exe'
$env:TRADELOOM_PYTHON = $python
$env:TRADELOOM_DB_NAME = 'tradeloom_dev'
$env:TRADELOOM_DB_HOST = '127.0.0.1'
$env:TRADELOOM_DB_PORT = '55432'
$env:TRADELOOM_DB_USER = 'tradeloom'
$env:TRADELOOM_DB_TEST_NAME = 'tradeloom_test_local_rollout'
$env:TRADELOOM_DB_PASSWORD = (Get-Content (Join-Path $env:LOCALAPPDATA 'PostgreSQL\tradeloom\superuser-password.txt') -Raw).Trim()
$env:TRADELOOM_MEDIA_ROOT = Join-Path $projectRoot 'data\runtime\uploads'
$env:TRADELOOM_ARTIFACT_ROOT = Join-Path $projectRoot 'data\runtime\artifacts'
$env:PGPASSWORD = $env:TRADELOOM_DB_PASSWORD

& $python -c "import os,json; from pathlib import Path; os.environ.setdefault('DJANGO_SETTINGS_MODULE','config.settings'); import django; django.setup(); from django.conf import settings; d=settings.DATABASES['default']; actual={'NAME':d['NAME'],'TEST_NAME':d['TEST']['NAME'],'HOST':d['HOST'],'PORT':str(d['PORT']),'USER':d['USER']}; expected={'NAME':'tradeloom_dev','TEST_NAME':'tradeloom_test_local_rollout','HOST':'127.0.0.1','PORT':'55432','USER':'tradeloom'}; assert actual == expected, f'Database identity mismatch: {actual}'; assert Path(settings.MEDIA_ROOT).resolve() == Path(os.environ['TRADELOOM_MEDIA_ROOT']).resolve(), 'MEDIA_ROOT mismatch'; assert Path(settings.TRADELOOM_ARTIFACT_ROOT).resolve() == Path(os.environ['TRADELOOM_ARTIFACT_ROOT']).resolve(), 'ARTIFACT_ROOT mismatch'; actual.update({'MEDIA_ROOT':str(Path(settings.MEDIA_ROOT).resolve()),'ARTIFACT_ROOT':str(Path(settings.TRADELOOM_ARTIFACT_ROOT).resolve())}); print(json.dumps(actual))"
if ($LASTEXITCODE -ne 0) { throw 'Django settings identity guard failed; stop before backup, migration, or startup' }
```

逐项确认输出的 `NAME`、`TEST_NAME`、`HOST`、`PORT`、`USER`、`MEDIA_ROOT` 与 `ARTIFACT_ROOT` 是本次预期目标后，再备份当前数据库和需要保留的媒体文件。备份目的地应位于仓库之外，使用新的时间戳路径，避免覆盖历史备份；至少用 `pg_restore --list` 检查 custom dump，并保存文件 SHA-256。不得把数据库密码写进命令参数、日志或文档。

对已有数据库先看目标 migration plan，再只应用计划中的迁移。当前本地这批对应的 plan 与迁移命令为：

```powershell
& $python manage.py migrate workbench 0003_workflow_create_idempotency --plan
if ($LASTEXITCODE -ne 0) { throw 'Migration plan failed; stop before applying migrations' }
& $python manage.py migrate workbench 0003_workflow_create_idempotency --noinput
if ($LASTEXITCODE -ne 0) { throw 'Migration failed; stop before startup and inspect actual database state' }
```

确认迁移成功后再启动当前源码。受控本地启动使用 `--noreload`，由同一 shell 继承上面已验证的环境变量：

```powershell
Start-Process -FilePath $python `
  -ArgumentList @('manage.py', 'runserver', '127.0.0.1:8000', '--noreload') `
  -WorkingDirectory $projectRoot -WindowStyle Hidden
```

随后只读检查新 listener 的 PID/命令行、`GET /api/health` 和需要使用的页面。`scripts/start-workbench.ps1` 会设置常规运行环境，但以 `runserver` 默认 autoreloader 启动；更新本机正式实例时使用上面的 `--noreload` 受控命令并单独核对进程树。启动脚本不会代替身份 guard 和备份。

不要为排障自动创建、清空、删除或重置数据库；不要用 `flush`、`DROP DATABASE`、`--clean` 或反迁移来处理迁移错误。失败后先只读检查 `django_migrations`、实际列和旧数据，再按证据决定下一步。数据库恢复演练只能恢复到经 catalog 确认不存在的新库；不能用恢复命令覆盖当前业务库。数据库恢复通过也不等于已验证旧进程的内存代码可精确回滚。
