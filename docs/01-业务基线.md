# 01 · 业务基线：外贸接单与交付协作需求

> 本文是项目讨论用的需求基线。公开版本只保留可复用的业务问题、设计假设与待验证项，不记录特定企业、客户、人员、经营金额或访谈原话。用户陈述、分析判断和待确认事项应分别标注；分析判断不能改写成客户已确认需求。

**整理日期**：2026-10-22  **版本**：v0.2（发布整理）

## 一、需求边界

本项目面向外贸接单场景，业务范围包括外购产品、后道加工、包装和出口交付中的协作。当前目标是验证哪些信息可以从现有文件和工作流程中可靠提取，再由人确认后进入产品；不是假定某个企业已有完整数字化流程，也不假定所有字段含义已经统一。

| 主题 | 当前可作为设计问题的内容 | 待访谈或验证 |
|---|---|---|
| 业务与组织 | 销售、采购、生产及交付环节可能由多人协作 | 企业类型、团队分工、产能与外协结构 |
| 客户与订单 | 询盘、报价、订单和跟进记录可能分散在不同载体 | 客户来源、客户关系维护方式、订单状态口径 |
| 商品与报价 | 商品规格、成本、报价与供应商信息需要可追溯 | 字段定义、金额精度、币种/单位/税运口径、审批状态 |
| 生产与工时 | 工序、排期、产量及工时信息可能需要采集和核对 | 标准工时与实际报工是否分别存在、日报载体与审核流程 |
| 经营与合规 | 订单、付款、收款和合规事项可能需要提醒与汇总 | 可使用的数据范围、计算公式、负责人及复核要求 |

## 二、协作链路假设

以下是待验证的产品机会，不代表客户已经确认采用这些功能：

1. **商品与内容准备**：整理商品资料、图片及规格，形成可检查、可复用的内容草稿；任何发布材料由人审核。
2. **客户与询盘协作**：统一记录客户来源、沟通事件和下一步动作；提醒与建议保留出处，由人决定是否联系。
3. **报价审阅**：把成本项、假设、适用单位与金额来源列清，输出可复核的区间或草稿；不得把估算值当作精确金额，也不得自动承诺价格。
4. **采购与供应商协作**：记录同规格询价、报价条件、交期及质量反馈；只有规格和计价条件可比时才生成比较结果。
5. **生产与交付跟踪**：把工序、计划、完成量和异常记录连接起来；只有实际数据来源明确时，才计算效率或预测交期。
6. **经营信息辅助**：按经确认的业务口径汇总订单相关数据，展示来源、公式和缺项；财务、税务及合规结论需由适格人员复核。

## 三、数据口径与来源原则

- 人工估算、标准/测时数据、实际逐日逐人报工是不同来源和不同口径，必须分别保存；不得由估算推出实际效率或工资。
- 金额记录可以被描述为较精确，但每项仍需核对原值、公式、缺项、单位、币种及确认状态；不能据此宣称所有金额已校验。
- 未提供或未确认的值保持未知或空缺，不用零值代替未知，也不从相似名称、规格、序号或颜色推断跨表身份关系。
- 每条候选事实都应保留原文件版本、工作表/单元格或范围、解析版本及确认状态。用户陈述、直接观察和分析推断分层记录。
- 公开自动化 fixture 与演示采用合成数据或经授权脱敏的样例；经授权的真实资料可在私有本地环境中验证导入、预览、计算与来源回溯，不进入公开仓库或演示材料。

## 四、待验证清单

- [ ] 组织角色、业务边界及销售/采购/生产/交付的实际协作方式
- [ ] 客户、商品、供应商、订单各自的稳定标识及字段定义
- [ ] 报价金额的来源、单位、币种、税运条件、公式和审批状态
- [ ] 工序标准、人工估算、实际报工分别有哪些记录和责任人
- [ ] 生产日报是否存在；载体、填报人、审核和修改方式
- [ ] 文件导入后哪些字段可以自动识别，哪些必须人工确认
- [ ] 产品价值与验收标准由实际使用者给出；公开验收使用合成或授权脱敏样例，授权真实资料可在私有本地环境验证

## 五、自动化边界

| 可辅助的工作 | 必须保留人工确认的事项 |
|---|---|
| 文件分类、字段候选、缺项提示和来源定位 | 确认业务语义、主键及跨表关系 |
| 汇总已确认的数据并展示公式和假设 | 批准价格、订单条件和对外交付承诺 |
| 根据明确规则生成提醒或待办 | 工资、绩效、人事、财务、税务及合规判断 |
| 起草客户沟通或内部摘要 | 发送消息、签署文件、付款或其他法律主体行为 |

## 六、证据状态

本基线由需求分析整理，不构成对任何特定企业状况的公开陈述。原始访谈与逐项来源记录保存在仓库外的私有工作区；本文件中可复用的设计原则与待确认问题不应被引用为已验证的客户案例。
