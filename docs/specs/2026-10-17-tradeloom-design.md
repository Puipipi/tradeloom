## 一、一句话

把一家工贸一体外贸企业「展会前最要命的那件事」做成一个能自己跑完的智能体：**20 张样品照片 + 一份价格表进去，一本能直接送印刷厂的画册页和一张有依据的报价单出来。**

### 1.1 赛题要求 → 我们的应答（答辩第一页就用这张表）

| 赛题要求 | 我们的应答 | 在 Demo 里哪里看见 |
|---|---|---|
| 基于 AgentArts 完成**构建、编排与部署** | 3 个智能体 + 1 条主控工作流，全部在智果内搭建并发布 | 投屏画布：节点、注释、连线 |
| **可视化 Demo 页面**展示核心功能与交互 | 拖拽上传 → 流程可视化 → 结果下载 → 人工确认 | 3 分钟视频主线 |
| 体现**智能体设计**价值 | Curator / Composer / Pricer 的职责切分与输入输出契约 | 每个智能体「吃什么、吐什么」一页 |
| 体现**工具编排**价值 | 代码节点（图片处理 / PDF 合成 / 成本计算）+ 插件 / HTTP 节点 | 校验不通过 → 自动重排的回路 |
| 体现**知识接入**价值 | 历史报价单、成本表、印刷规格、客户画像入 KooSearch | 报价依据点开可追溯 |
| 体现**多 Agent 协作**价值 | 主控分发 + A 的产出直接接 B 的输入 | 「接缝」那 20 秒 |
| 体现**效果评估**价值 | 四项指标 + 20 单回测 + 平台观测 | 评测页两个数字 |
| **闭环实践**：场景识别→架构→编排→调试→上线 | 六周排期本身就是这条闭环 | 时间轴一页 |
| **分享帖**（入围后） | W6 产出，按赛题建议的五段结构 | 文档链接 |

> **判断**：评分的落点大概率不在「功能多」，而在「五环节是不是都看得见」。所以每一个环节都要有**对应的页面或截图**，缺一个就是缺一分。这也是为什么我们在架构里刻意留了「校验器重试回路」（工具编排）和「报价依据」（知识接入）——它们不是功能，是证据。

### 1.2 对着官方评分表校准（初赛创新性 60%）

| 官方评分点 | 我们靠什么拿分 | 短板 / 应对 |
|---|---|---|
| 场景创新 | 不是"再做一个客服"，而是**展会前 15 天**这个具体死线；痛点有老板原话 | — |
| 与现有方案差异化 | 现有工具要么是排版软件（不认业务），要么是 ERP（要录入）。我们**不换系统、从既有行为取数** | 要讲清"为什么不能直接用 Canva/稿定"，答案：它们不懂成本表，也不认印刷规格校验 |
| **设计思路 / 交互方式创新** | ①人在环：Agent 只给区间与依据，不拍板；②**决策回流**：老板改过的价成为下一次的依据；③校验器不通过自动重排 | 这是初赛 60% 的主战场，必须在视频前 60 秒就出现 |
| 应用价值（40%） | 真实死线、可量化（合格率、命中率、耗时） | 落地数据要真实，宁可小 |

**对演示脚本的两个硬要求**（来自「基于 AgentArts 构建与运行的完整流程」这句）：

1. 视频里必须有**画布镜头**：节点、连线、逐个跑起来的状态；不能只有结果页。
2. 保留一次**失败重试**：校验不通过 → 自动重排 → 通过。这 5 秒是最能证明"它真的在干活"的镜头。



## 二、为什么是 A+B，不是单选

| | A 单独 | B 单独 | A+B |
|---|---|---|---|
| 评委第一眼 | 看得到成品 | 看不到成品，像表格 | 先看到成品，再看到脑子 |
| 创新性叙事 | 弱，容易被当"排版工具" | 强 | 强（有实测指标） |
| 6 周可行性 | 高 | 中（依赖数据） | 中高（必须分工） |
| 共同地基 | 成本模型 | 成本模型 | 一份成本模型，两条链复用 |

关键：**A 的终点正好是 B 的起点**（A 产出报价单，B 接着算这个单该报多少），所以两条链不是拼起来的，是接起来的。这条"接缝"就是答辩时最好讲的一句话。

## 三、演示脚本（3 分钟，先写脚本再写代码）

| 时间 | 画面 | 说什么 |
|---|---|---|
| 0:00–0:30 | 真实场景：广交会前 15 天，桌上一堆样品和 Excel | 「这家企业有 20 个人，没有 ERP，没有 CRM。老板说：报多少价合适？这个『度』从哪里来？」 |
| 0:30–1:50 | 拖入 20 张样品图 + 价格表 → 流水线自己跑（识别/抠图/规格化 → 排版 → 生成 PDF → 自检规格） | 「它不认识这家公司，但它认识印刷厂的要求：CMYK、300dpi、3mm 出血、字体转曲。」 |
| 1:50–2:30 | 报价单自动生成 → 点开任意一行看依据 | 「每一个数字都能点回它来自哪份成本表、哪一单历史成交。」 |
| 2:30–2:50 | 问：「德国客户 A 要 5000 件，报多少？」→ 区间 + 理由 | 「它不是替你拍板，它把你能拍板所需的东西摆齐了。」 |
| 2:50–3:00 | 老板改一个价，系统记下这次决策 | 「改过的每一次，都会变成下一次的依据。」 |

## 四、架构（AgentArts 上长什么样）

### 4.1 三个智能体 + 一条主控工作流

```
ExpoWorkflow（主控工作流：意图识别 → 分流 → 汇总 → 人工确认 → 归档）
├── Curator   视觉与规格化   多模态识别品类/材质/尺寸 → 抠图 → 统一色值与尺寸
├── Composer  排版与交付     版式规则 + 中英卖点文案 → 合成 PDF → 印刷规格自检（不过就重试）
└── Pricer    报价陪跑       知识库检索 + 成本拆解 → 区间 + 依据引用 + 一次性说明
```

- **Curator**：输入原图，输出"可用素材 + 结构化属性"（品类/材质/尺寸/主色/建议卖点角度）。
- **Composer**：把素材排进版式；输出物必须过规格校验器（见 4.3）。
- **Pricer**：不做自动报价，只输出「区间 + 依据 + 风险提示」，人确认后写入决策日志。
- **ExpoWorkflow**：一个入口吃两种活；用户在 Demo 页面选"我要做画册 / 我要报价 / 两个都要"。

### 4.2 平台组件映射

| 需求 | 用 AgentArts 的什么 |
|---|---|
| 主体智能体与提示词 | 智能体管理（大模型、意图识别、消息节点） |
| 多步流程 | 工作流编排画布（每个节点加注释，答辩时直接投屏） |
| 历史报价单 / 成本表 / 印刷规格 / 客户画像 | 知识库（KooSearch） |
| 图片处理、PDF 合成、成本计算 | 代码节点（FunctionGraph） |
| 外部能力（如需要） | HTTP 请求节点 / 插件 |
| **加分项** | 把「印刷规格校验」做成一个 **Skill / MCP 工具**（赛题原文提到 MCP、Skills、插件开发在范围内） |
| 演示界面 | 可视化 Demo 页面（拖拽上传 + 流程可视化 + 结果下载） |
| 效果证明 | 平台的观测与评估 + 我们自己的回测脚本 |

### 4.3 规格校验器（这是 A 的护城河）

印刷厂交付的硬指标，逐项自动检、不通过就让 Composer 重排：

| 检查项 | 判定 |
|---|---|
| 色彩模式 | 全部 CMYK，无 RGB 残留 |
| 分辨率 | 每张图 ≥ 300 ppi（按实际印刷尺寸换算） |
| 出血 | 四边 3 mm |
| 字体 | 全部转曲或嵌入 |
| 文件格式 | PDF/X-4（或厂方指定版本） |
| 总墨量 | ≤ 300% |
| 小字黑 | 单黑 K100，非四色黑 |
| 页数 | 4 的倍数 |

> 这张表就是"处理成印刷厂要的格式"的可执行定义。**能通过它，才算做完**；这也是答辩时最能证明"不是玩具"的一页。

### 4.4 数据流

```
样品图 + 价格表 → [Curator] → 素材清单.json
                                    ↓
                          [Composer] → 画册页.pdf  ─┐
                                    ↓              ├→ 报价单.pdf（同源价格）
历史成交/成本表 → [Pricer] ←──────────┘
                    ↓
              区间 + 依据 + 决策日志
```

## 五、数据

最小可跑集（对应 [03-数据与素材清单](../03-数据与素材清单.md)）：20 张样品原图、1 份价格表、1 份印刷厂要求、≥30 单历史成交（脱敏）。拿不到真实数据时，用**公开素材 + 明确标注"合成数据"**，绝不含糊。

## 六、评测（不然只是"能跑"，不是"有用"）

| 指标 | 怎么测 | 目标 |
|---|---|---|
| 画册页合格率 | 20 张图 → 20 页，逐项过 4.3 校验表 | ≥ 90% |
| 报价区间命中率 | 20 单历史回测：实际成交价是否落在建议区间内 | ≥ 70% |
| 依据可追溯率 | 抽查 10 条建议，能否点回原始单据 | 100% |
| 单页耗时 | 从上传到出 PDF | < 90 s |

> 数字难看也算成果——答辩时讲"我们第一次只有 45%，改了版式规则和尺寸推断后到 88%"，比一个漂亮数字可信。

## 七、六周排期（3 人）

| 周 | 目标 | 产出 |
|---|---|---|
| W1 | 平台跑通 + 细则确认 + 数据到位 + **申请云资源代金券** | hello-world 工作流；赛题二分值细则；第一批素材；分工定死；MaaS Token Plan 与云资源代金券申请已提交 |
| W2 | Curator 通 | 图 → 结构化素材清单（含抠图与尺寸推断） |
| W3 | Composer 通 | 单页 PDF + 校验器（先做 A4 单页与价格页，不做整本画册） |
| W4 | 编排 + Demo 页 | ExpoWorkflow 串起来，Demo 页面可录屏 |
| W5 | Pricer + 评测 | 报价区间与依据；两张评测表跑出数 |
| W6 | 交材料 + 起英文版 | 3 分钟视频（含画布镜头与一次失败重试）、技术文档、**社区分享帖（早发，攒阅读量）**、报名材料；英文答辩稿提纲（总决赛 +2 分） |

## 八、分工（按能力互补，不按资历）

| 角色 | 负责 | 交付 |
|---|---|---|
| 甲 · 视觉/前端 | Curator、Demo 页面、演示视频 | 能录屏的界面 + 成片 |
| 乙 · 后端/函数 | PDF 合成、成本计算节点、校验器、评测脚本 | 可复现的代码与数字 |
| 丙 · 数据/产品 | 知识库语料、报价逻辑、回测、技术文档与分享帖 | 语料 + 文档 |

三人共同：每周一次 30 分钟对齐，只问三个问题——**这周产出能不能跑？跑出来的东西对得上真实业务吗？下周的演示能不能更短？**

## 九、明确不做（写进"未来工作"，别偷偷做）

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| AgentArts 能力假设不成立（不能跑 Python、文件出入受限） | **W1 逐项验证**，见第十一节；不成立就退回"HTTP 节点 + 外部服务" |
| PDF/X-4、CMYK 转换做不出来 | 降级为 PDF 1.7 + 嵌入 ICC，并在文档里说明偏差 |
| 拿不到 30 单历史成交 | 报价模块降级为"成本拆解 + 规则区间"，诚实标注数据规模 |
| 三人时间不齐 | 按周冻结"可演示版本"，宁可功能少，不可周末空手 |
