# 企业服务端与个人端快速入门

## 分发与首次设置

服务端和 Electron 个人端分别分发。服务端保存企业数据库及运维配置；个人端只连接服务，不携带服务器数据库或运维秘密。老板版可另附完整 Workbench；工厂版不附 Workbench。两种个人端使用独立 profile，程序版本不代替服务器角色授权。

1. 将完整 Server 包解压到新目录，使用运行服务的 Windows 账号启动 `Start-Server.ps1`。首次安装会准备独立运行环境、数据库并提示创建管理员。自行输入账号和密码；不分发管理员密码。
2. 默认数据目录为 `%LOCALAPPDATA%\TradeLoomEnterpriseServer`，HTTP 27417、PostgreSQL 56427 均仅供本机使用。首次可用 `-DataRoot <新专用目录> -Port <HTTP端口> -PostgresPort <数据库端口>` 选择独立目录及空闲端口；两个端口须不同且在1024至65535。不要停止别的安装腾端口。
3. 在同源 `/admin/` 创建日常账号、分配角色；普通业务账号无需职员或超级管理员。安装超级管理员也可从控制台进入“工厂与登记员设置”。
4. 解压对应个人端并运行 `TradeLoom 企业服务器客户端.exe`，自行输入服务地址并正常登录。本机示例为 `http://127.0.0.1:27417`；远程必须使用已配置的 HTTPS 来源，不填 `/enterprise/` 路径。首次地址为空，不预置账号密码。

后续以相同 Windows 账号、相同 DataRoot 启动，复用原数据及保存端口。停止使用随包 `Stop-EnterpriseServer.ps1 -DataRoot <原目录>`。解压新 ZIP 不会自动更新旧 DataRoot 内复制的应用；已有部署升级须单独安排备份、迁移和验收。不要删除数据目录重置登录。

详细 HTTPS 配置及外接数据库说明见[企业服务部署](enterprise-service.md)。随包 Django runserver 用于 loopback 开发验证；公网生产部署需要独立 WSGI、TLS、访问策略和备份方案。

## 角色及入口

| 身份 | 授权与入口 |
| --- | --- |
| 企业老板 | 加入“企业老板”，保留默认业务读取及全部登记权限；企业首页、控制台、已接入业务只读页、公告及凭据管理 |
| 工厂登记员 | 加入“工厂登记员”和对应“工厂:简称”组；只见本人私有登记与所属工厂共享登记，可新建登记 |
| 服务运维员 | 显式授予 `enterprise_portal.use_server_operations`；只用控制台诊断，不获得业务、账号管理或凭据写入权限 |
| 管理账号 | 通过 Django admin 的实际权限管理用户和组；老板身份本身不授予账号管理权限 |

登记员身份和明确运维身份的业务拒绝规则优先；误加高权限组不能解除这些组合限制。服务端每次请求检查权限。老板可在“用户组权限矩阵”查看单组授权，在成员详情核对直接权限、实际组和组合限制；单组矩阵不等于成员最终权限。客户端菜单也重新查询服务能力。

安装超级管理员可在“工厂与登记员设置”创建无权限的工厂范围组、创建登记员、调整所属工厂或停用合适的普通登记员。混合角色、直接权限、staff/superuser 和带权限工厂组须转到 admin 核对。切厂和停用在后续请求生效，旧记录不会移动。

## 业务与本地工作台

企业首页的“批次与商品”“客户名录”“来源报价记录”只查询当前企业数据库已接入字段。来源报价经过关系与数值校验，不是商品价目或实时 ERP；空库显示空状态，不自动导入个人资料。工厂和运维身份不能使用这些业务页。

“打开本地完整工作台”只启动另附的本机 Workbench，使用其自身数据、配置与模型登录。企业台账与本机资料不自动合并；登记员版本不附完整工作台。应用角色不能限制用户另行获得的本机程序和 Windows 文件权限。

## 助手与企业公告

老板或授权运维员从 `/enterprise/console/` 使用固定诊断命令。自然语言分类须由老板配置 DeepSeek API Key，且用户明确同意发送本条问题；只发送问题，不发送数据库或凭据。模型只能选择已有读动作或建议表单，不执行任意 Shell、SSH、URL 或直接写入。

老板输入 `发布公告 正文`、`替换公告 正文` 或精确的 `撤下公告`，在本地准备提案；这些固定命令无需模型。核对完整正文、当前版本后点击相应确认按钮并再次确认才提交。取消不写入；刷新不替换提案的版本基准。冲突时展示最新公告，必须重新核对并明确确认。手动公告表单仍可使用。公告为1–500字纯文本，显示于已登录企业登记站；技术员只能查看，登记员不能调用运维写接口。

## 凭据与可选站点运维

仅老板可写入或删除 Cloudflare API Token、Zone ID、OAuth client secret 和 DeepSeek API Key。服务端以当前服务 Windows 账户 DPAPI 加密并校验专用 vault ACL；无秘密回读接口，个人端不保存这些秘密，状态仅表明是否配置。换服务账户或重装系统需重新录入。删除当前密文不代表远端吊销或历史备份清除。反向代理和错误收集不得记录凭据请求体。

Cloudflare 默认不联网。显式查询才核对已配置单 Zone 的域名与状态；老板核对 active 域名后，可明确确认清理一个公开 HTTPS 资源路径。拒绝外部 URL、查询串、编码、点路径及双斜线；不支持 DNS、全站清理或任意请求。OAuth secret 不能代替 API Token。成功表示供应商接受请求，不证明边缘缓存已清空。

OpenSSH 网页入口只读服务及有限配置声明，未知或解析受限不代表有效登录权限；不修改 Windows 组、密钥、服务或防火墙。可选本机入口见[本机控制台](enterprise-local-console.md)，OS 管理员工具见[SSH 专用组管理](local-ssh-group-management.md)。

## 分发核对

使用与发布提交对应的独立 Server 和个人端 ZIP，核对发布摘要及包内源清单。不要打包服务 DataRoot、profile、vault、凭据、日志或测试证据。快捷方式须指向选定版本，首次设置说明须与该包一致。现有安装保持原位，先在独立目录及独立数据目录验证新包，再安排升级。
