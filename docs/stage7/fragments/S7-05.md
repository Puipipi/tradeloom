# S7-05 Django 自有业务页面

冻结基线 `69e65681d407c5993cb364dd0965a4b29806fab6`，tree `4a1685c69dc5e6a0eee5a1a6904b9e6bd5e9f244`。许可清单 30 个源码、10 个测试；全部 owner/baseBlob 及 12 个只读依赖 blob 与冻结树匹配。

| 生产入口 | 页面资源和契约 |
| --- | --- |
| `/customers`、`/customers/<customer_id>` | `customer_list` / `customer_detail` → `customers.html` / `customer_detail.html` → `customers.js`。表单绑定依赖既有 ID、class 和 data 属性；`customer_api` 接收现有 JSON，提交保留 same-origin、CSRF、错误码映射和错误展示。别名、跟进决策、按日期评估/校准、身份操作原先各自复制禁用按钮 → 提交 → 刷新，失败显示错误并解禁；现共用 `submitCustomerChangeAndReload`。候选事件可能跳到客户详情，回测在当前页渲染并总是恢复按钮，因此留在各自处理器。私有 `bindReloadForm` → `bindAsOfCustomerChangeForm`，`bindActions` → `bindCustomerActionDecisions`。 |
| 基础模板 → Agent 运行 | `base.html` 加载 `agent-run-receipts.js`；页面消费 `AgentRunReceipts`。私有 `scope/read/write` → `pendingReceiptScope/readPendingReceipts/persistPendingReceipts`。以任务和能力组合隔离 pending 回执；发请求前确认持久化，运行中或未知结果保留回执，确认结束后清理。全局 API、存储键、字段及重试边界未改。 |
| `/artifacts`、`/workflow-tasks/<workflow_id>` | `artifacts.html` 将资料、录入与执行计划交给各自脚本；执行计划通过已确认需求版本读写计划版本。`workflow_detail.html` 的 `workflow-graph.js/css` 消费业务计划图与步骤数据，保留节点图/列表、适应、缩放、整理及审核动作。无模板、样式、布局、画布或工具栏 diff。 |
| 业务嵌入和运行记录 | `base.html` 加载 `business-url.js` 与 `app.js`；`runs.html` 加载 `run-filters.js`，保持嵌入消息、路由、筛选、窄宽及组件滚动契约。 |
