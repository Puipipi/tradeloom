## 局部验证

Node 24.16.0，SDK 来自 `[local-path-redacted]`（manifest `0.2.2-rc.3`），测试数据、只读 SDK 解析预加载脚本及 TAP 位于 `[local-path-redacted]`。测试只运行清单内文件。MCP 使用既有本地惰性 stdio peer，音频使用 SDK 事件日志与受控合成回调。

- 完整六文件使用同一个 `node --import file:///<proof>/resolve-sdk.mjs --test --test-reporter=tap <六个分配文件>` 与相同 SDK/临时根。冻结基线退出 1，16/23，通过数见 `baseline-exact.tap`。候选退出 1，21/23，通过数见 `candidate-exact.tap`。五项差额来自 MCP 四项与音频一项由冻结夹具的 rc.2 断言失败，转为在获准 rc.3 SDK 实际执行通过。
- 同一预加载下运行 MCP、记忆目录、记忆图和音频四个文件，退出 0，14/14，见 `controlled-integration.tap`。另用 `--test-name-pattern '^(only completed|queue is serialized|rebind aborts|agent disposal|concurrent controller|onAudio may|an asynchronous)'` 跑朗读控制器，退出 0，7/7，见 `controlled-speech.tap`。MCP 实测本地 peer 建连、取消、等待旧子进程退出后替换、隔离 Agent 工具、拒绝旧实例和撤销操作。音频实测 SDK 最终事件到 Host poll、拒绝自报文本和旧绑定。
- 基线与候选均复现 2 个缺口。导航共享 fixture 要求另行提供固定 rc.2 desktop postimages 输入及 rc.2 SDK，本轮只有指定 rc.3 SDK。Windows 本地 System.Speech fixture 使用合成文本，宿主返回 `session_speech_provider_unavailable`。实机网页登录、附件、保存、外部模型、实际 GUI、安装与打包留集中验收。
