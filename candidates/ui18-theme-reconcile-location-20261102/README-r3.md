# UI18 theme reconcile failure location candidate

## Revision r3

This revision keeps the r2 baseline and wire unchanged. It fixes two lookup issues: the receipt path now obtains `profileContext` through Cordis `ctx.get('profileContext')`, matching AppBoot's existing preflight path; and known SDK/runtime frames remain eligible when no profile root is available. The original `README.md` and `SOURCE-SHA256.txt` describe the prior E60C2D freeze and are preserved as historical records; because the candidate `after/` files were revised, use only `SOURCE-SHA256-r3.txt` for current byte verification.

This isolated candidate adds a bounded, opaque location projection to the existing UI18 theme write failure receipt. It does not change reconcile, CAS, rollback, settings-write, or error propagation behavior and has not been installed into the UI18 ASAR.

## Projection contract

`host-error` may contain `introducedFailureLocation` and `applyFailureLocation`. Each is exactly:

```json
{"entry":"p202","file":"p202-f00001","line":75,"column":11,"type":"TypeError"}
```

`entry` and `file` contain only values from the generated opaque code tables, or `unknown`. `line` and `column` are positive safe integers only when `file` is known; otherwise both are `null`. `type` is one of `TypeError`, `ReferenceError`, `SyntaxError`, `RangeError`, `URIError`, `EvalError`, `AggregateError`, `Error`, `other`, or `unknown`.

The AppBoot helper checks exactly one failed introduced entry. Entry fallback accepts an exact package specifier or an exact statically declared file path (absolute path, `file:` URL, or relative specifier resolved against that Loader entry's `parent.tree.ctx.baseUrl`). It performs string/path normalization only; it does not import, resolve through Node, stat, or read the entry target. A known stack frame takes precedence over entry-only fallback. For stack selection, one direct `cause` is checked first, then the original error; deeper causes are not traversed.

Stack reading is fail-closed. At module initialization AppBoot captures the current `Error.stack` descriptor and `Error.prepareStackTrace` descriptor. It invokes only the captured stack getter when the current getter, setter, and descriptor attributes still match, and never invokes the setter or changes the formatter. A native Error with its own data-string stack is also supported. The native header is derived from bounded `name` and `message` data descriptors (never by calling `Error.toString()` or a user getter), matched and removed exactly; multiline messages are allowed, and any pseudo-frame lines inside the header are excluded from frame parsing. Parsing is bounded to the first 8 KiB and first 12 `at` frames. Paths must exactly match the private static map; messages, raw stacks, package names, and filesystem paths never enter the receipt.

`profileRoot` is optional during frame lookup. When absent, only exact runtime-map paths can match; profile-relative and business-shell aliases do not match without their respective roots. The helper continues to check the exact static map and does not probe or resolve files.

`main-location-validator.mjs` is the Main-side copy of the finite `entry`/`file`/`type` code sets and shape checks. It contains no package names or paths. The private `location-map.private.json` is only for AppBoot's exact lookup and must not be sent to Main or included in a receipt. The internal projection helper is not part of the AppBoot export surface; the recovery Vitest loader appends a temporary test-only export in memory.

## Static map provenance

The private map is generated by `recovery-20261029/ui18-theme-reconcile-location-20261102/scripts/build-private-location-map.mjs` from fixed inventories:

- The local DSH plugin migration inventory and junction manifest. The generated map covers 332 declared packages, 11,519 executable program files, and 641 declared profile aliases. It maps declared `.plugins/p/NNN` and manifest-proven aliases; package/file codes are path identities, not proof that a module was loaded.
- The frozen UI18 `desktop-runtime.json` manifest: 17,168 indexed files, of which 12,404 are executable program files. SDK file codes preserve the original zero-based manifest index. Only `dsh/` runtime paths are eligible.
- The frozen business-shell package manifest and its 47 declared executable files. This is mapped under `resources/tradeloom/business-shell/` and the declared profile alias `node_modules/@tradeloom/dsh-business-shell/`; it is not treated as a migration `p/NNN` package.

The source manifest hashes and counts are embedded in the private JSON. Static declarations do not prove current runtime bytes, module loading, or that a mapped frame caused the product failure. Any unknown or ambiguous path remains unknown.

## Files and integration boundary

The AppBoot and ConfigEditor TypeScript files are cumulative source mirrors based on the candidate `before/` snapshots, which already contain prior compiled-only reconcile metadata edits. Those `before/` TypeScript hashes do not match today's pinned `sdk-complete` source hashes; see `recovery-20261029/ui18-theme-reconcile-location-20261102/SOURCE-SHA256-r3.txt`. The three compiled `before/` snapshots match the prior r2 candidate's compiled `after/` files; they are not a separate live-ASAR verification. Their compiled JavaScript files are manually mirrored, targeted candidate edits, not a full SDK build. SettingsController is a compiled-only candidate edit. The revision-specific unified diff is `recovery-20261029/ui18-theme-reconcile-location-20261102/SOURCE-r3.patch`; the private map and code-only Main validator are separate files. Do not apply the cumulative source mirror blindly to current SDK source or replace a whole SDK tree from this candidate. The existing production receipt has no new RPC or stage; the two optional objects are projected on its existing `host-error` row.

This revision has isolated owned-fixture evidence under the companion recovery directory. A real Cordis `Context` fixture verifies `ctx.get('profileContext')` returns the provided profile object. A real Node TypeError thrown from a deterministic runtime-map filename maps without a profile root; existing tests continue to cover profile-root mappings. No formal ASAR, user profile, settings, session, or account data was read or modified. The candidate does not establish a product root cause or prove the packaged Electron/V8 runtime's stack descriptor; the captured-descriptor behavior was exercised with Node v24.16.0.
